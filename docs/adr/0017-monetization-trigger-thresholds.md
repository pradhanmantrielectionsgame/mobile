# ADR-0017: Pre-Committed Thresholds for the Capacitor + Monetization Build

## Status

Accepted (2026-09-04)

## Context

The game is about to ship to the Play Store as a **TWA** (Trusted Web Activity)
generated by PWABuilder — a Chrome window pointed at
`https://pradhanmantrielectionsgame.com/`, bundling no content of its own. That
raised the question of monetization, and the investigation found that both
obvious routes are structurally blocked by that architecture:

**Ads are impossible in a TWA.** Chrome renders the whole screen, so a native
`AdView` cannot be overlaid. Injecting AdSense into the PWA instead violates
AdSense/AdMob policy for webview and native-wrapper contexts; the sanctioned
route is the WebView API for Ads via the Google Mobile Ads SDK, which requires a
native host. There is an open feature request against `android-browser-helper`
(#535) precisely because no supported path exists.

**IAP needs a backend.** The Digital Goods API and Payment Request API do work
in a TWA (Chrome 101+), but a purchase not acknowledged within 72 hours is
auto-refunded and revoked, and entitlements need server-side validation to mean
anything. This project has no backend — static GitHub Pages only — and the
unlock progression is deliberately client-side `localStorage` (ADR-0005).

**Gating the web version is also unavailable.** A TWA *is* the website, so
taking the site down or redirecting it to the Play listing breaks the Android
app too: it follows the redirect off-origin, loses asset-link verification, and
shows the browser address bar. Serving the game only to app traffic (via a
`?src=twa` start URL or the `android-app://` referrer) is possible but
client-side and spoofable — the same weakness as the `localStorage` unlocks.

So every real monetization move — ads, content gating, or IAP — routes through
the Capacitor migration already accepted in ADR-0003. That is one migration
serving all three, and it should be paid for once, at the right time.

The risk this ADR exists to manage is motivated reasoning: deciding after the
fact that whatever numbers arrived were good enough to justify work already
wanted for its own sake.

## Decision

**Ship the TWA now with the existing Buy Me a Coffee tip link, and do not start
the Capacitor + monetization build until all three gates below pass.**

The tip link stays because it costs nothing and carries no policy risk:
Play requires Play Billing for purchases of in-app *digital content*, but
donations are explicitly outside that requirement, and this one grants no in-app
benefit. **If a tip is ever wired to unlock anything — politicians, for instance —
it stops being a donation and becomes an in-app purchase that must go through
Play Billing.** Don't wire them together.

### Gate 0 — Measurement (prerequisite, not a threshold)

GoatCounter is pageview-based with no persistent user identity and **cannot
measure retention**. Play Console reports D1/D7/D30 for free once the app is
live. Shipping the TWA is therefore the measurement instrument, not just a
distribution experiment. Optionally instrument a "game completed" GoatCounter
event for session depth.

### Gate 1 — Retention (the go/no-go, checked before volume)

2026 benchmarks: industry median D1 ≈ 26%; a "good" profile is D1/D7/D30 =
35/15/5; top quartile clears 40/20/10. Puzzle/strategy sits near 32/12/5.

| | Bar |
|---|---|
| D1 | ≥ 25% |
| D7 | ≥ 10% |
| D30 | ≥ 4% |

**If D7 < 8%, do no monetization work at any download number.** Monetizing a
leaky bucket converts churn into pennies; fix the game first.

### Gate 2 — Volume (MAU, not downloads)

Rewarded-only model. Interstitials between phases are rejected outright — they
would wreck the deliberate per-phase action pacing (see CLAUDE.md's "avoid
click-fest mechanics" and `planAITickPacing`).

```
revenue/month ≈ MAU × ~8 sessions × ~1.5 rewarded views × eCPM/1000
              ≈ MAU × 12 impressions × eCPM/1000
```

| MAU | @ $2 eCPM | @ $5 | @ $15 |
|---|---|---|---|
| 1,000 | $24/mo | $60 | $180 |
| 5,000 | $120/mo | $300 | $900 |
| 10,000 | $240/mo | $600 | $1,800 |

Against roughly 20–40 hours for the Capacitor migration plus AdMob, plus
permanent native build/release maintenance.

**Floor to bother: ~5,000 MAU. Clearly worth it: ~10,000 MAU.**

The 10,000-*downloads* figure tracked in the marketing push is an **initial
distribution target, not the ultimate goal and not a monetization trigger** — at
typical retention it implies roughly 500–1,500 MAU, or $12–36/month. Keep the
two numbers separate.

### Gate 3 — Organic growth

Play Store organic discovery growing month-over-month without manual promotion.
If installs only arrive when a Reddit post goes up, monetization does not fix
that.

## Consequences

**Positive:**

- The launch is not blocked on a monetization decision that cannot be
  implemented in what is being shipped.
- Play Console supplies the retention data the decision needs, for free, as a
  side effect of launching.
- One Capacitor migration unlocks ads, content gating, IAP *and* the backend
  that multiplayer needs (ADR-0002) — evaluated together rather than ads alone.

**Negative:**

- No revenue beyond tips for at least a few months.
- The thresholds are pre-committed from benchmarks, not from this game's own
  data, so they may prove miscalibrated for a turn-based strategy game with
  ~10–15 minute sessions. Revise deliberately and in writing, not silently.

**The variable most likely to change the answer:** eCPM. Tier 1 rewarded runs
$18–45, global average $10–22, and India is materially below that (no sourced
India figure was found; don't invent one). GoatCounter's country breakdown
already answers this — a largely-India audience uses the low column, while a
significant US/UK diaspora share shifts the table up 5–10× and could make
monetization viable at roughly half the MAU. Check the dashboard before
anchoring on any row.
