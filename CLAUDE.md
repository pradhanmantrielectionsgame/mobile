# Project Instructions — PradhanMantri Elections Game Mobile

Terse, current-state rules only. Full narrative history behind each one (dates, user reports, measurements, reverted attempts) is archived in `findings.md`'s 2026-09-03 "CLAUDE.md pre-simplification archive" entry — grep there before assuming a rule has no backstory worth checking.

## UI conventions

- Small UTs (Delhi, Chandigarh, Dadra & Nagar Haveli and Daman & Diu, Puducherry, Lakshadweep, Andaman & Nicobar Islands) are never directly tappable on the map — route through the `union-territories-container` button-cluster (paired with the timer-pill) instead. J&K and Ladakh are large enough to tap directly.
- `mobile/index.html` (+ `engine.js`/`game.js`/`ai.js`/`main.js`) is the real, playable build — the only place to edit game logic. `design/prototypes/pme-mobile-sheet.html` is a frozen, unmaintained design reference (demo logic only, don't edit). Root `index.html`/`styles.css` no longer exist on this branch. Run `npm test` and `npm run serve` (open `/mobile/index.html`) after changes.
- `scripts/deploy-mobile.js` builds a flattened, path-rewritten copy of the runtime files (`mobile/*.js`/html, `assets/`, `data/`, `sounds/`) into a worktree tracking the `mobile` remote's `main` branch and pushes from there. Run it (`--push`) whenever `mobile/` changes and the live site needs to catch up.
- Multiplayer (live human matchmaking) is out of scope until requested — needs an external Firebase/Supabase backend. A full implementation-ready plan already exists at `design/multiplayer-implementation-plan.md`; point a future session there instead of re-deriving the architecture.
- Politician special-power numbers and portrait art (20/20) are complete. Only 4/20 politicians have a dedicated power-sound clip; the rest fall back to the generic `fanfare` via `playPowerSound()`.
- "Share result" screenshots the real `.declare-card` via vendored `mobile/html2canvas.min.js` — don't remove it or revert to a hand-drawn card (rejected once for showing only "half" the result).
- The politician-select carousel and end-of-game screen use Booth Ink's light-theme "ballot card" identity (tricolor stripe, brass seal, ticket-stub die-cut) — see `design/prototypes/pol-card-mockup.html`. The app has no dark mode anywhere; don't add one here.
- Don't reintroduce raw per-politician agenda bonus numbers in the select-screen UI — replaced by `agendaEffectChips()`'s tap-to-expand region breakdown reading `policy-tags.json`.
- The app's entry point is the full-bleed `#welcomeOverlay` welcome screen, not the politician-select screen directly.
- The ~69 emoji used as UI icons render in each OS's own emoji font (Apple/Noto/Segoe), so the app looks different per platform. Accepted 2026-09-04 — don't propose an emoji webfont or a Twemoji SVG swap. Windows-captured screenshots showing Segoe emoji are expected, not a bug.
- India's map SVG viewBox (`84 27 833 946`) already tightly bounds the landmass (~2-6% margin). The empty NE/SE regions are ocean space, not letterboxing — don't try to scale/crop to fill them; design floating panels to occupy that dead space instead.

## Game design principles

- `docs/wiki.html` is the single authoritative reference for finalized game design — check it first for "how is X supposed to work." Keep it in sync in the same session a mechanic/constant changes. `design/economy-status-map.md`, `design/plan.md`, `CHANGELOG.md`, `findings.md` are all dated history, not current-state references.
- Avoid click-fest mechanics — cap actions per phase so each has real opportunity cost.
- Regional/group dominance bonuses require **every** state in the group individually >50% popularity, not a seat-weighted average — deliberate, not a bug.
- Investment-boost decay (`boostDecayRate` in `game-config.json`) must keep decaying geometrically past its cap rather than flattening to a permanent floor, or a cheap group member (e.g. a 1-seat UT) becomes a free permanent veto on the whole group's payout.
- A group held at phase start also pays a small flat recurring "holding bonus" (`holdingBonusCrPerSeat`, currently 0.5 Cr/seat after repeated reductions) on top of the one-time crossing bonus — deliberately non-compounding. It's symmetric, so balance-sim win-rate won't move when tuning it — watch hung-parliament rate and seat-lead width instead. It's paid per-group without deduplicating overlapping states, so an *asymmetric* human capture of many groups can be lopsided in a way AI-vs-AI sims can't surface.
- For economy/balance work, the desktop app's real code (`game-config.js`, `state-info.js`, `campaign-spending.js`, `home-state-bonus.js`, `group-rewards.js`, `state-groups.js`) is ground truth — except mobile's base economy *scale* (starting funds 5,000, refresh 2,500/phase, cost = seats×10), which is independently canonical and not benchmarked against desktop's numbers. Formula *shapes* still follow desktop.
- A policy's regional pull is a per-(policy, region) signed magnitude (`policy-tags.json`'s `tagEffects: {region: magnitude}`), always one of ±4/±8/±12, using the same 15 region keys as the regional-dominance groups. Read `policy.tagEffects[group.key]` directly (via `agendaGroupEffects()`) rather than re-deriving it from a redistribution simulation.
- When a state carries several tags for one policy (some supporting, some opposing), sum to one net value first and apply it through the redistribution engine exactly once — never as separate sequential transactions (the 100%-cap and proportional split are non-linear per transaction).
- A special power's cost must be a genuine resource sacrifice (funds/popularity/tokens) — never just a timing gate or eligibility condition, since those cost nothing when the power is actually usable. Explicit, deliberate exceptions exist (`requiresMinPhase` on Patel/Modi/Indira/Ambedkar/Rao, each with a real-world timing rationale) — don't add more without an equally explicit call-out.
- A one-phase-duration power must set its expiry to the current `game.phase` at activation, never `+1` (a banned delayed-trigger bug). Modi's Demonetization is a deliberate two-phase exception (`fundsFrozenUntilPhase = game.phase + 1` paired with a `<=` range check) — active immediately, not delayed.
- When a region-tagged policy's seat-equivalent comes out sharply negative, check for accidental same-state cancellation between its own support/oppose tags before assuming deliberate polarization. A handful of intentional zero-net cancellations exist as of 2026-08-26 (Administrative Reform/MP, Environmental Conservation/Jharkhand, Nationalization/AP+TN+WB) — accepted tradeoffs, don't "re-fix" without checking with the user.
- Also sanity-check a policy's tag sign/region choice against real Indian political geography, as a pass distinct from magnitude/cancellation checks.
- Track popularity/redistribution in integer bps (0–10000), never float. Splitting a change 2-way: round one side, derive the other by subtraction. For any N-way conversion to whole units (e.g. seats), use largest-remainder (Hamilton's) apportionment, never independent rounding per share.
- A greedy per-action scoring formula (cost-efficiency, boost/cost) must account for remaining headroom (score on `min(gain, headroom)/cost`, not raw gain) and must normalize by what's actually being bought (e.g. per-seat, not raw %-per-Cr) — otherwise it gets stuck re-targeting an already-maxed or tiny-but-"efficient" option.
- An AI targeting function must not return a strict argmax over a pool the human also draws from under a shared cap (e.g. rally targets under `rally.maxPlaysPerStateShared`) — use a value-weighted random draw (`weightedRallyPick`) instead, or the bot both plays identically every game and eats the human's access to top targets. Pure single-player power-targeting (no shared cap) can stay argmax.
- Whenever a human-facing UI restricts an action (a batch-only button, a disabled tap target), check the AI's engine-level code for the same restriction — it bypasses `main.js`'s DOM layer and acts directly on `game` state, so it usually isn't restricted by default (see `SMALL_UT_BATCH_IDS` for the fix pattern).
- AI strength/behavior changes must preserve even, human-comparable real-time pacing (`planAITickPacing()`) — never an instant catch-up burst.
- The 4 celebrity picks (Tendulkar, Hema Malini, Rajinikanth, Bachchan) plus Sivaji Rao are deliberately stronger/quirkier on their **special power** specifically — not their agenda kit, which stays a deliberate thematic match. Current post-rebalance numbers are in `data/politicians-data.json` / `docs/wiki.html`'s Special Powers section.
- A "steal"-style power must explicitly choose seize (`seizeFundsPct`/`seizeTokens` — opponent's resources destroyed) vs. steal (`stealFundsPct`/`stealTokens` — transferred to activator), never default to whichever primitive exists.
- A power targeting the exact states in a mobile HUD quick-invest button group (e.g. `#neBtn`'s Northeast-8) should use the `svgIds` scope in `resolvePowerScope` with that button's own ID list, not a broader `tags` scope that happens to overlap.
- A politician can have more than one home state via `secondaryHomeStates` — every consumer of `homeState` must read through the `homeStatesOf()` helper, not the raw field, or a multi-home politician silently loses the bonus somewhere. `generateStartingPosition()`'s draw budget must be seeded with 25% of each player's own home-state seats (matching the home bonus's own magnitude) so a big/multi-home politician doesn't get an uncompensated stacked advantage.
- When tuning a randomized mechanic's parameters, verify the resulting distribution via direct mean/σ simulation, not inference from percentiles or intuition about which knob controls what.
- For AI-*profile*-strength questions, run `mobile/ladder-sim.js` (seat-margin round robin with mirrored pairs + a monotonicity check) — not `balance-sim.js`, which never varies AI profile and can't attribute results to one. Re-run after any shared `aiStep` change. Never read a single flag's ablation delta as that flag's standalone value — it's conditional on every flag below it in the chain.
- For politician/agenda balance questions, run `mobile/balance-sim.js` and read **win rate**, not avg final seats. See `design/testing-and-balance-notes.md` for methodology traps.
- Hung parliament is always a draw (`finalizeGame()`, ADR-0010). When changing what a game-outcome field means, grep for every place that independently re-derives the same conclusion (not just where the field is read) — this codebase has hit that "two places must agree" failure before.
- A special power's deliberate-max seat swing should stay at or under ~50 seats, measured via a realistic full-game AI-vs-AI playthrough (not a blind average or frozen starting position).
- When building/editing an agenda kit, check its net effect in that politician's own home state specifically, not just overall kit balance.
- The politician-unlock progression is deliberately client-side (`localStorage`) and bypassable via devtools — accepted, not a bug. Don't propose hardening it; real enforcement needs a server-authoritative backend, out of scope until multiplayer is.

## Architecture constraints

- Don't rewrite this game in React Native/Flutter — the UI is DOM/CSS/SVG-heavy with no native-performance need. Wrap the existing vanilla HTML/CSS/JS with Capacitor instead.

## Legal & branding constraints

- Don't formally incorporate a company or file an Indian trademark under a name containing "Pradhan Mantri" (or other PM-referencing phrase) without prior Central Government permission (Emblems and Names Act, 1950). Not a blocker for the current informal `.com` setup — revisit before ever formalizing the business. See `findings.md` (2026-09-04).
- Among the roster, Bachchan and Rajinikanth carry the highest personality-rights legal exposure (both have direct, on-point Indian case law naming them); the rest of the roster is lower risk, and political figures get extra "core political speech" protection Rajinikanth specifically doesn't have (never held office). No restriction found on depicting real party symbols. See `findings.md` (2026-09-04) for full reasoning; revisit before reworking either roster entry or any commercial push.

## Versioning

- SemVer via `package.json`'s `version` (reset to 1.0.0 on 2026-08-23; the earlier ad-hoc `2.0.0`–`2.0.5` numbering is retired). Patch = bugfix/tweak, minor = new feature/mechanic, major = breaking save/data-format change. Docs-only commits don't bump it.
- `/checkpoint <version>` uses that version as the CHANGELOG.md header — bump `package.json`'s `version` to match in the same commit (manual, not automated).
- CHANGELOG.md keeps an empty `## [Unreleased]` header at the top at all times; new session content gets its own fresh version header, not a growing Unreleased block.
- `mobile/main.js`'s `GAME_VERSION` constant (drives the `v1.0.0` badge on welcome/HUD/end-card) must be bumped by hand alongside `package.json`'s version — it can't `require()` package.json from browser code.

## Data & config conventions

- Prefer config/data files (JSON under `data/`) over hardcoding values in JS — matches the existing `game-config.json`/`config-manager.js` single-source-of-truth pattern.
- Don't mint a new agenda tag for just one politician — needs 2+ real, distinct biography fits to clear the bar. The shared pool (`data/policy-tags.json`, 32+ entries) is large; prefer a weak/generic slot over a single-use tag.
- Politicians draw 4 agendas from that shared pool plus one unique special power — multiple politicians can share an agenda. Don't build a per-politician bespoke agenda table.
- No CRUD tool wanted for `politicians-data.json`/`policy-tags.json` — edits happen via direct natural-language requests to Claude. Run `check_data_consistency.js` after any edit.
- The legacy desktop reader (`js/config-manager.js`, `js/data-loader.js`) reads config via hardcoded key names with no fallback defaults — any schema change to `game-config.json`/`politicians-data.json` must preserve those legacy keys (hence `mobile/`'s new constants live in the additive `mobileEconomy` namespace).
- `policy-tags.json`'s content is under a `policyTags` key, `politicians-data.json`'s under `politicians`, and `states_data.json` has a leading UTF-8 BOM — any Node script reading these directly (not via browser `fetch`) must unwrap the key and strip the BOM (see `stripBOM()`/`normalizeGameData()` in `mobile/game.js`).
- `mobile/engine.js` has no `module.exports` — it's a UMD-style global (`global.PMEEngine`). A Node script needing it directly must `require(path)` then read `global.PMEEngine`, not destructure the `require()` return.
- `craftToken()` (crafting the Special Powerup / Nationwide Rally) is not subject to `maxTokenSpendPerPhase`, unlike `playRallyToken()` — relevant to any token-economy balance work.

## Local development & testing

- Engine math (`investCash`, `dominanceActive`, `nationalSeats`, `aiStep`) and DOM/CSS size are all confirmed healthy as of the 2026-08-29 perf audit — this project's real performance cost lives in assets and DOM work, not game logic. Don't re-audit without new evidence.
- See `design/testing-and-balance-notes.md` for dev-server/LAN setup, the manifest `start_url` gotcha, and Playwright/AI-testing caveats.
- When handing the user a phone-testable URL for `npm run serve` (port 8934), use a `cloudflared tunnel --url http://localhost:8934`, not a bare `localhost` URL — it won't resolve on the test device.

## Frontend technical rules

- Never set `touch-action:manipulation` in `mobile/index.html` — it still permits pinch-zoom. Use `touch-action:pan-x pan-y`.
- Never rely on CSS Grid shrink-to-fit with `1fr` tracks for a declared pixel/icon size — give the grid container an explicit screen-relative width instead.
- Every standalone HTML file must declare `<meta charset="UTF-8">` as the very first tag.
- Calibrate mobile UI sizing against the real iPhone 14 viewport (390×844), not how it looks inside the Claude Artifact viewer (which adds ~150-200px of its own chrome).
- A collapsible tray hidden via `max-height:0` still occupies its full flex width — use `position:absolute` instead of relying on collapsed height for width-neutrality.
- Honeycomb/hex row layouts: alternate row item counts (N, N−1), center each independently — no manual offset needed.
- Verify Safari-specific mobile bugs (viewport meta, safe-area-insets) with Playwright's `webkit` engine + `devices['iPhone 14']`, not Chromium (which ignores the page's own viewport meta tag).
- `devices['iPhone 14']`'s `viewport` is 390×664, not 844 (844 is the `screen` field) — judge fixed-chrome fit against 664. A clean Playwright/WebKit pass is not sufficient evidence for viewport-meta changes — verify on a real device or Capacitor build too (a dynamic-viewport-meta fix once passed Playwright cleanly but badly broke real iPhone Safari).
- `mobile/index.html` has a real `width=device-width` tag and fluid `rem` scale (since v2.0.0) — author new CSS at real intended pixel sizes (`rem`/`--fs-*`/`--radius-*` tokens), not the old 2.5×-authoring convention. Borders/shadows scale too now (keep them modest, ~1-2px).
- The map SVG renders Uttarakhand/Ladakh/Himachal Pradesh as a duplicate-ID `<circle>` overlay on top of their `<path>` — map interaction code must query `path[id], circle[id]` together.
- Use `fill-opacity`, not `opacity`, to dim SVG map states (plain `opacity` also fades the stroke).
- Any element toggled via the `hidden` attribute needs an explicit `<selector>[hidden]{display:none}` rule if that selector's base class already sets its own `display` — author CSS otherwise beats the UA default at equal specificity. Hit 4 times already (`.overlay`, `.group-readout`, `.target-banner`, `.vs-bar`).
- A decorative flex item with no intrinsic content (e.g. a spacer/color-stripe span) needs explicit `width:100%` — it collapses to zero width whenever the flex parent's `align-items` isn't the default `stretch`.
- iOS Safari blocks `.play()` on an `<audio>` element until that specific element has played from within a real user gesture at least once (per-element, not per-page) — any sound that only ever fires from a non-gesture context (timer, AI turn) must be included in `unlockSounds()`'s startup unlock pass.
- Any fallback/alternate sound path must preserve whatever audio-ducking state is already active, not reset volume before playing the fallback.
- A new fixed-position UI element must be checked against `.ut-bar` (full-width HUD strip at `bottom:14px`) and `.pol-footer`'s Play button before assuming the screen's corners/bottom edge are free.
- iOS Safari's ITP caps script-writable storage (`localStorage`, Cache API) to ~7 days of inactivity unless the site is installed to the home screen — no code fix, just prompt users toward Add to Home Screen.
- `<audio>` elements have real (100ms+) playback-start latency that no JS reordering fixes — only Web Audio's `AudioBufferSourceNode` does. Reserve pre-decoded buffers (`primeTapSfx()`/`playTapSfxBuffer()`) for rapid tap-feedback SFX specifically; background/non-gesture sounds stay on plain `<audio>`.
- A bookmarked (non-home-screen) iOS Safari tab aggressively auto-suspends `AudioContext`; `.resume()` is async, so always check `sfxCtx.state === 'running'` before claiming a Web Audio play succeeded, and fall back to `<audio>` if not.
- Raster assets must be sized to their actual display resolution (not 2048² for a ≤400px render) and shipped as WebP, not PNG, for photographic art with no alpha channel — check both dimensions and format before adding any new asset. Same applies to auto-traced SVGs rendered small (rasterize them; coordinate-rounding barely helps).
- Bind game actions to `pointerdown` via `fastTap()` (`mobile/main.js`), never `click` — `click` can't fire until finger-lift, adding 70-120ms of dwell latency that's invisible to Playwright's synthetic taps. Keep the politician carousel on `click` (needed to distinguish swipe from tap) — any new scrollable/swipeable surface should too.
- Tap-feedback CSS must animate `transform`/`opacity` only, never `width`/`height`/`margin` (forces layout+paint every frame).
- Batch DOM reads (`getBoundingClientRect()`) before writes (`appendChild`) in any per-render loop — interleaving forces a synchronous layout per iteration.
- Anything positioned from a JS measurement of another element's box needs a `ResizeObserver` on that element, not calls scattered at each mutation site (the caller list is never complete).
- Never hang a DOM node off the `game` object — `planAITickPacing()`'s `structuredClone(game)` throws on it, and the throw happens after `game.rng` is nulled, silently killing the AI. Use a module-level side map keyed by id instead.
- A `loading="lazy"` image inside a `hidden` subtree never fires `load` — use `new Image()` if you need to preload behind an overlay.
- `mobile/sw.js` is network-first with `{cache:'reload'}` for app shell/code/JSON (bypasses GitHub Pages' HTTP cache-control so deploys land immediately) and cache-first for media — don't apply `{cache:'reload'}` to media or repeat visitors re-download ~20MB of art every load. Media lives in its own `MEDIA_CACHE`, which `activate()` must never evict on a shell version bump, and whose media branch must keep its `.catch()` — both together are what stopped sounds silently dying after a deploy. `mobile/sw-check.js` (in `npm test`) guards this.
- `pme-mobile-media-v1` in `mobile/sw.js` is a placeholder: `scripts/deploy-mobile.js` stamps it from a content hash of `assets/` + `sounds/`. Never hand-bump it.

## Deployment

- Live URL: `https://pradhanmantrielectionsgame.com/` (replaced `kaunbanegapradhanmantri.in`, retired 2026-09-04 after a NIXI serverHold — see `findings.md`). DNS at Porkbun: 4 `A` records → GitHub Pages IPs at root, `www` CNAME → `pradhanmantrielectionsgame.github.io`.
- This repo has exactly one remote, `mobile`, with two branches: **`mobile/main`** = the flattened deploy build (written only by `scripts/deploy-mobile.js`, never push source here) and **`mobile/source`** = this full source tree (what local `main` tracks). Push source with plain `git push`; ship with `node scripts/deploy-mobile.js --push`. The separate desktop-game repo (`pradhanmantrielectionsgame.github.io`) is untouched by any of this — clone it separately to work on it.
- `scripts/deploy-mobile.js` strips the `../` asset prefix by literal string match (`'../assets/'`, `'../data/'`, `'../sounds/'`, `'../' + p.image`, `'../' + p.partyLogo`) — write asset paths in exactly those forms, never via an intermediate variable, or the rewrite silently misses them (404s live, not a build error). Dry-run `stripRelativePaths()` and grep for surviving `../` before any push.
- `scripts/deploy-mobile.js` ships a hand-maintained file allowlist — any new runtime file under `mobile/` must be added to it in the same commit that creates it, or it silently vanishes from the live build. Diff `<script src>`/`<link href>` in `mobile/index.html` against the script's copy list before deploying. `assets/`, `data/` and `sounds/` are the opposite — copied wholesale, so anything added under them ships with no allowlist edit.
- Commit source changes before running `node scripts/deploy-mobile.js --push` — it copies from the working tree but labels the commit with `HEAD`'s sha, so a dirty run mislabels what shipped. After pushing, poll the live site rather than curling once immediately — GitHub Pages CDN takes ~40s to propagate.
- Never extract a store package into the working tree **or its parent directory** — PWABuilder's zip carries `signing.keystore` plus its passwords and this repo pushes to a public remote. Store packages live in `D:\keys\`. (`assetlinks.json`'s fingerprint is public and is correctly committed.)
- `.gitignore` has **no effect on a file Git already tracks**, and neither a clean `git status` nor a positive `git check-ignore` is evidence a secret is safe — this repo leaked its signing keystore that exact way (see `findings.md`, 2026-09-05, and ADR-0018). Before trusting an ignore rule on sensitive material, run `git ls-files | grep -i <pattern>`; tracked state is the only thing that counts. Untracking needs `git rm --cached`, and a force-push does not remove the blob from GitHub — only rotation or a GitHub-side GC does.
- The TWA `.apk`/`.aab` contain **no game code** — they are a ~2.7MB `androidbrowserhelper` wrapper around `https://pradhanmantrielectionsgame.com/index.html`. Game changes reach installed apps through `deploy-mobile.js` alone; rebuild the package only for wrapper-level changes (package name, icon, splash, launch URL, target SDK, signing key). The corollary is that a bad deploy breaks every installed app instantly with no store-review buffer, so `npm test` before `--push` carries more weight than it looks like.
- Real play counts are tracked via GoatCounter (`https://pradhanmantrielections.goatcounter.com`), not GitHub repo Insights (which only sees git/repo-page activity, not the deployed game).
